# Visual hierarchy (Nielsen Norman Group)

Source: Kelley Gordon, "Visual Hierarchy in UX: Definition", NN/g, 2021. https://www.nngroup.com/articles/visual-hierarchy-ux-definition/

- Definition: organizing design elements so the eye takes them in the intended order of importance.
- Three tools: **color and contrast**, **scale**, and **grouping** (proximity and common region).
- It is the contrast in value and saturation between an element and its context, not the color itself, that creates hierarchy.
- Limit variation: few colors; at most about three contrast variations ("if everything is contrasted, nothing stands out"); about three sizes; at most two large elements.
- Saturated color for the important; reserve warm bright colors such as red for warnings and errors. Don't rely on color alone.
- More space around an element makes it read as a group and draws attention. Containers (borders, backgrounds) help when space alone isn't enough, but add clutter, so use them sparingly.
- **Squint test:** blur the design (5 to 20px) to see the hierarchy that actually reads. Content can break a template's hierarchy (a strongly colored image can dominate), so judge with real content.
- Define the content hierarchy first, then apply contrast, scale, and grouping, then check it reads as intended.
